# ADR-003: Списание токенов за AI-генерацию (premium-only + token-spend)

- **Статус:** Accepted
- **Дата:** 2026-06-10
- **Контекст модуля:** AI-генерация, premium / billing, backend
- **Отношение к другим ADR:** дополняет [ADR-002](ADR-002-adapty-bearer-auth-token-economy.md) (начисление токенов вариант Б). ADR-002 ввёл **начисление** токенов webhook'ом; ADR-003 определяет их **списание**. Закрывает Q-BILL-1 / [TD-002](../100-known-tech-debt.md#td-002--списание-токенов-за-ai-генерацию-не-спроектировано).

## Context

ADR-002 ввёл реальную токеномику (вариант Б): подписка начисляет токены на `User.tokens`. Списание токенов за AI-генерацию (`POST /ai/generate-theme`) осталось неспроектированным и было зафиксировано как открытый вопрос Q-BILL-1 / TD-002. В результате баланс рос без оттока, а экономика фичи была неполной.

Открытые вопросы из TD-002, которые требовалось закрыть:
- стоимость одной AI-генерации в токенах;
- поведение при нулевом/недостаточном балансе (hard-block `402`/`403` либо fallback на curated-слово);
- приоритет «баланс токенов» vs «`is_premium`-безлимит» (списываются ли токены у premium);
- атомарность списания и устойчивость к гонкам параллельных запросов одного device_id.

Дополнительное продуктовое решение: AI-генерация по произвольной теме становится **premium-фичей** (free-юзеру AI недоступен).

## Decision

### 1. `POST /ai/generate-theme` — premium-only

- AI-слово выдаётся только premium-пользователю: `User.is_premium == true` И (`premium_expires_at` is null ИЛИ `premium_expires_at > now`) — та же проверка, что в `GET /categories/{id}/words`.
- Не-premium (включая отсутствующего в БД пользователя) → curated fallback, `fallback_reason: premium_required`, HTTP 200, токены не трогаются. Контракт ответа (`AIThemeResponse`) не ломается — клиент по reason показывает paywall.

### 2. Стоимость и условие списания

- Стоимость одной фактической выдачи AI-слова = `AI_THEME_TOKEN_COST` токенов (env, default `1`).
- Списание — ТОЛЬКО при фактической выдаче AI-слова: как свежая LLM-генерация, так и отдача из Redis pool-cache premium-пользователю.
- На ЛЮБОЙ fallback токены НЕ списываются: `premium_required`, `rate_limit_exceeded`, `moderation_rejected`, `insufficient_tokens`, `ai_unavailable`.

### 3. Недостаточный баланс

- Premium с `tokens < AI_THEME_TOKEN_COST` → curated fallback, `fallback_reason: insufficient_tokens`, HTTP 200. Баланс не уходит в минус (нет hard-block `402`/`403` — единообразно с остальными fallback'ами; клиент обрабатывает как успех).

### 4. Rate-limit сохраняется как анти-абуз потолок

- Существующий rate-limit для premium (50/24h/device) остаётся поверх токеномики. Превышение → fallback `rate_limit_exceeded`, токены не списываются.
- Free-лимит `ai_theme_free` (5/24h) фактически не достигается, т.к. не-premium отсекается раньше на premium-gating; остаётся в конфиге как defensive потолок.

### 5. Атомарность и устойчивость к гонкам

- Выдача AI-слова — Redis-операция (`sadd` pool/history), списание — Postgres `UPDATE`. Единой ACID-транзакции Redis+DB не существует, поэтому атомарность обеспечивается на уровне строки `User`, а корректность связки «выдано ↔ списано» — порядком шагов (§6).
- **Conditional decrement атомарен на уровне строки User:** `UPDATE users SET tokens = tokens - :cost WHERE id = :id AND tokens >= :cost` с проверкой `rowcount`. Параллельные запросы одного `device_id` не списывают сверх баланса и не уводят баланс в минус: при гонке только один `UPDATE` затронет строку.
- При `rowcount = 0` (баланс уже исчерпан параллельным запросом или `tokens < cost`) → fallback `insufficient_tokens`; AI-слово не отдаётся как платное, фиксация выдачи в Redis-историю не выполняется (§6).

### 6. Порядок проверок (нормативный)

1. Валидация запроса (`400` на пустой/несанитизируемый topic).
2. Авторизация (`X-Api-Key`, валидный `X-Device-Id`).
3. Premium-gating → `premium_required`.
4. Rate-limit (анти-абуз) → `rate_limit_exceeded`.
5. Blacklist / модерация темы → `moderation_rejected`.
6. Проверка баланса → `insufficient_tokens`.
7. Подбор AI-слова-кандидата (pool-cache / fresh LLM; LLM недоступен → `ai_unavailable`, unsafe-результат → `moderation_rejected`). На этом шаге слово ещё НЕ фиксируется в device-историю.
8. Атомарное списание `AI_THEME_TOKEN_COST` (conditional decrement, проверка `rowcount`; `rowcount = 0` → `insufficient_tokens`).
9. **Только при успешном списании (`rowcount = 1`):** фиксация выдачи — `sadd device_history` (Redis) + возврат AI-слова. При неуспехе списания (шаг 8) Redis-история НЕ меняется, отдаётся fallback `insufficient_tokens`.
10. Лог `AITopicRequestLog` + ответ с `tokens_remaining`.

**Нормативный порядок «decrement → фиксация»:** conditional decrement (шаг 8) выполняется ДО фиксации выдачи в `device_history` (шаг 9). Это исключает рассинхрон вида «слово помечено выданным в Redis-истории, но токен не списан»: пока списание не подтверждено `rowcount = 1`, слово не считается выданным и не пишется в историю.

### 7. Контракт ответа

- В успешный ответ и в premium-fallback'и добавляется поле `tokens_remaining` (int, nullable) — баланс после обработки (при успехе уже за вычетом стоимости). Для не-premium / неизвестного устройства — `null`.
- `fallback_reason` enum расширяется: `premium_required`, `insufficient_tokens` (вдобавок к `ai_unavailable`, `moderation_rejected`, `rate_limit_exceeded`).
- `AITopicRequestLog` не меняется в этом scope; логирование списанных токенов — опционально (не обязательно).

### 8. `POST /ai/generate-words` (admin) не затрагивается

- Admin-эндпоинт (admin-key) токеномикой не охватывается — токены не списываются.

### ENV

| ENV | Тип | Default | Назначение |
|---|---|---|---|
| `AI_THEME_TOKEN_COST` | int | `1` | Стоимость одной фактической выдачи AI-слова в `POST /ai/generate-theme`. |

## Consequences

**Положительные:**
- Баланс токенов получает отток — экономика фичи замкнута (начисление ADR-002 + списание ADR-003).
- Единообразный «тихий fallback»: клиенту никогда не отдаётся hard-error за нехватку токенов/премиума — всегда HTTP 200 + curated word + reason.
- Атомарный conditional decrement исключает двойное списание и уход в минус при параллельных запросах.
- Стоимость генерации настраивается env без пересборки.
- `tokens_remaining` даёт клиенту актуальный баланс без дополнительного запроса `GET /users/me`.

**Отрицательные / риски:**
- Backend обязан добавить `AI_THEME_TOKEN_COST` в `config.py` + `.env.example` и реализовать списание (задача backend).
- AI-генерация становится недоступной free-юзерам — продуктовый компромисс ради монетизации; поведение покрывается `premium_required` (клиент показывает paywall).
- Отдача из pool-cache теперь тоже тарифицируется — premium-пользователь платит за каждое слово, даже если оно уже было сгенерировано ранее другим устройством (осознанное решение: «слово» — единица тарификации, не «LLM-вызов»).

## Alternatives

1. **Hard-block `402`/`403` при нехватке токенов / отсутствии premium** — отвергнут: ломает существующий «тихий fallback»-контракт `/ai/generate-theme` (клиент ожидает HTTP 200 + `AIThemeResponse`), усложняет клиент. Выбран единообразный curated fallback с `fallback_reason`.
2. **Premium = безлимит без списания токенов (только начисление)** — отвергнут: баланс токенов остался бы без оттока (исходная проблема TD-002); токены как валюта потеряли бы смысл.
3. **Списывать только за свежую LLM-генерацию, pool-cache бесплатно** — отвергнут: создаёт неравномерную тарификацию и стимул эксплуатировать общий pool; единица тарификации — выданное «слово», а не факт LLM-вызова.
4. **Best-effort списание после фиксации выдачи (сначала `sadd history`, потом decrement)** — отвергнут: допускает расхождение «слово помечено выданным в Redis-истории, но токен не списан» при гонке/сбое decrement. Корректный способ — атомарный conditional decrement (atomic на уровне строки User) ПЕРЕД фиксацией выдачи: история пишется только при подтверждённом `rowcount = 1` (§6). Единой ACID-транзакции Redis+DB нет, связность обеспечивается порядком шагов.
5. **Оставить AI доступным free-юзерам со списанием токенов** — отвергнут продуктовым решением: free-юзер не имеет источника токенов (токены начисляются только подпиской, ADR-002), поэтому списание у free бессмысленно; AI делается premium-only.
